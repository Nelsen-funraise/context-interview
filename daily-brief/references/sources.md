# 來源登錄表（把這一份填成你們公司的）

> **這是整個 skill 唯一需要「組織適配」的檔案。** 其他檔案是簡報方法本身、通用、不用動。
> 拿到這個 skill 的第一件事：照下面的分類把你們實際的資料源登錄進來、
> 然後把每一節的「填寫指引」刪掉。這份會過時——資料源增減時直接改這份檔。

這份檔案的用途只有一個：**讓簡報裡的每一個數字都能被追回去。**

沒有這份表、簡報就是一個要求讀者相信它的黑箱。第一次數字看起來怪、他又查不到來源的時候、這份簡報就結束了。所以規則很硬：

> **寫得出數字、就寫得出它從哪裡來、以及他自己去哪裡看。**

寫的時候要區分三種東西、它們的用途不一樣：

| | 是什麼 | 給誰用 |
|---|---|---|
| **來源標註** | 這個數字是從哪個系統的哪張表算出來的 | 讀者判斷可信度 |
| **回溯連結** | 點下去直接到那一列／那一頁 | 讀者要看細節 |
| **原始資料入口** | 他自己要重新查、換條件查的地方 | 讀者不信、或想深挖 |

三種都要有。只有第一種是在自我聲明；加上第二、三種才是可被檢查的。

## 寫法規範（通用、不用改）

### 每個數字後面接一行來源

```
參與率 33.3%
來源　GA4 〈property 名〉 · engagedSessions ÷ sessions · 8/17 單日
看原始　analytics.google.com → 〈property〉 → 取得流量 → 工作階段預設管道群組
```

字級比正文小、顏色淡、不要跟內容搶。**但不要省略**、也不要合併成「資料來源：GA4、Notion」這種一整份共用一行的寫法——那等於沒有標、讀者無法對應到具體哪個數字。

### 每一列任務都要能點開

任務、專案、會議記錄、名單、查詢的時候把 `url` 欄位一起選出來、輸出時掛在標題上。**沒有連結的任務清單不要出現在簡報裡**——讀者看到「這張還沒動」的下一個動作就是打開它、這一步不能讓他自己去搜。

### 算式要寫出來

不要只給結果。「377 / 1,064 = 35%」比「35%」可被檢查。特別是比率、環比、平均這三種——它們最容易因為分母定義不同而差很多。

### 資料品質三問、每天都要答

1. **這個期間完整嗎？** 當日資料通常不完整（GA4 有延遲、GSC 延遲 2–3 天）、不完整的期間要排除或標註。
2. **分母變了嗎？** 新管道的第一期基準是 0、任何「成長 ∞%」都是假的。
3. **這個為 0 是真的 0、還是沒接到？** 最重要的一問。名單表是空的、可能是廣告沒效、也可能是名單根本沒流到這張表。**兩種的行動完全不同、分不出來就要明講分不出來**、並指名該問誰。
