# 個人設定檔

## 存哪裡

優先放在使用者自己的 Notion 私人頁面（標題建議「每日簡報設定」）。理由：他自己看得到、改得動，而且不需要額外的權限設計。

找不到就在對話裡問他要放哪，不要自作主張放在共用空間——設定檔裡會有「我不想看到 X」這種資訊，那是私人的。

## 內容

```markdown
# 每日簡報設定 — ⟨姓名⟩

## 模組
- ⟨模組名稱⟩

## 特別關注
- 專案：⟨…⟩
- 對象／客戶：⟨…⟩
- 指標：⟨…⟩

## 不要出現
- ⟨…⟩

## 寄送
- 時間：⟨…⟩
- 管道：⟨…⟩

## 修訂紀錄
- YYYY-MM-DD ⟨改了什麼、為什麼⟩
```

## 怎麼演進

**第 1 天**：只給骨架，設定檔留空。不要一開始就問他想要什麼——人在看過之前答不出來，而且那個問題會讓他覺得這是一件需要他投入的事。

**第 2–3 天**：觀察他的回應。他跳過哪一段、對哪一段有反應、抱怨什麼。

**第 4 天起**：他開始給具體回饋時，才更新設定檔。**回饋是「這個不該出現」時，優先照做**——刪比加重要。簡報變短通常會變好。

**每次修訂都記進修訂紀錄**，寫清楚為什麼。這樣三個月後看到某個奇怪的設定時，知道它是為了解決什麼問題。

## 一個常見的錯誤

使用者說「我也想看 X」時，不要直接加一個新段落。先問：X 是每天都要看，還是想到才看？**想到才看的東西不該進每日簡報，應該做成一個他隨時可以叫的 skill。**

每日簡報的位置很珍貴——它是唯一一個不用他主動就會出現的東西。塞進去的每一段都在消耗那個特權。
