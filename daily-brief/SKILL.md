# 每日簡報

## 這份簡報要做到的事

一份好的每日簡報，判準只有一個：**它要告訴使用者至少一件他不知道、但該知道的事。**

只重述已知資訊的簡報沒有價值，會在三天內被關掉。所以這份 skill 的重點不是「把資訊蒐集齊」，是**把散在不同來源的東西接起來**——一封信解鎖了哪幾張卡住的票、一個逾期任務跟另一個逾期任務其實是同一條線、某家公司同時出現在會議記錄和登記異動裡。這些連結才是使用者自己做不到的部分。

閱讀時間控制在 90 秒。超過就會變成另一個待讀清單。

## 權限與誠實

**這份簡報只能用執行者自己看得到的資料產出。** 連接器是以執行者的身分認證的，所以讀到什麼就是他本來就能讀到什麼——不要在文案裡暗示系統有更大的視野。

三件不能做的事：

- **不要編造。** 找不到的資訊就說找不到。寧可短，不要填充。
- **不要推測成事實。** 「這封信可能代表…」要標成推測；「這封信說…」才是事實。
- **不要在第一階段索取。** 初期版本不要出現「請你去補 XX 欄位」。使用者還沒依賴它之前，任何索取都是成本。等他主動說「這個怎麼沒抓到」，那才是可以開口的時機。

## 來源回溯：每個數字都要能點回去

這是這份簡報跟一般 AI 摘要的差別，也是它能不能被信任的分界。

**規則**：寫得出數字，就寫得出它從哪裡來、以及讀者自己去哪裡看。三件事都要有——

1. **來源標註**：這個數字從哪個系統的哪張表、用什麼算式算出來的
2. **回溯連結**：點下去直接到那一列、那一頁
3. **原始資料入口**：他要自己重查、換條件查的話，開哪個畫面

只有第一項是在自我聲明；加上第二、三項才是可被檢查的。

**任務清單沒有連結就不要出現。** 讀者看到「這張還沒動」的下一個動作就是打開它——不要讓他自己去搜。查詢的時候一併把 `url` 欄位選出來。

**比率要寫算式。** 「377 / 1,064 = 35%」比「35%」可被檢查，而比率最容易因為分母定義不同而差很多。

系統清單、資料源 ID、原始資料入口的實際路徑，以及排版寫法，見 `references/sources.md`。

## 先確認自己讀對了地方

**一個部門的工作不一定在你第一個想到的那個資料庫裡。**

多數組織同時有好幾套任務系統在跑（全公司一套、部門自己一套、工程另一套）。實測過的教訓：某個部門的人主要工作在部門自己的任務庫、只讀全公司那套會漏掉他八成的工作——而且讀到的那兩成常常是跨部門協作的殘留、逾期天數很大、但不是他今天該做的事。

所以做任何人的第一份簡報之前，先花五分鐘確認：

- 他的**任務**在哪個資料庫？他的**專案**在哪個？
- 他的部門有沒有自己的工作區（例如 `MKT` 在 XDC 底下，不在 Universal 那一層）？
- 他的**會議記錄**進哪一套？公司至少有四套平行的會議記錄庫
- 他負責的**外部資料**有幾個？分析工具常常是多個 property、多個站、不是各一個

這一步查錯，後面所有判讀都會偏，而且偏得很有自信。

## 產出結構

固定的骨架加上可選模組。骨架每天都在，模組依個人設定檔決定——詳見 `references/modules.md`。來源少到撐不起骨架時、見下一節。

**骨架（一定有）**

1. **今天最重要的一件事** — 只有一件。找不到夠格的就誠實說今天沒有特別的，不要硬湊。這一段要包含：發生了什麼、來源、以及**它連動到什麼**（這是最有價值的部分），最後給一句具體的建議動作。
2. **今天的行程** — 從行事曆來。標出使用者是不是主持人，以及空檔在哪。
3. **逾期任務** — 依逾期天數排序。若有逾期超過 60 天的，要點出來並說明那通常代表狀態沒更新而非進度落後。

**可選模組** — **清單唯一的出處是 `references/modules.md`**：使用者或訪談設定選了那裡有的模組就照做、不要因為別處沒列到而拒絕。

**收尾（一定有）** — 透明度區塊：讀了什麼、沒讀什麼、怎麼停、這一版不會要你做任何事。這四句是初期建立信任的關鍵，不要因為篇幅省略。

## 沒有公司資料源時的最小可用版

不是每個人都接了公司系統。只接得到一兩個來源、甚至什麼都沒接、簡報照樣要出——但**不要輸出空簡報、也不要用常識填版面**。沒讀到行事曆卻寫「你今天有三個會、記得提早準備」、被抓到一次就沒有人會再打開它。

- **只有行事曆**：頭條（今天最重要的那件事）從行程本身找——哪一場他要主持、哪一場前面完全沒有空檔、哪一場的對象是外部的。逾期任務那一區直接不出現、不要留一個空標題在那裡。
- **只有信箱**：頭條找等他回覆最久的那一封、附連結。
- **什麼都沒接**：改成一頁「你自己說過的事」——訪談記錄檔裡他講過的每週重複工作（今天星期幾就列今天那幾件）、他自己訂的目標、昨天那份簡報留下的建議動作。這些是他說過的話、不是查來的資料、來源行要寫「來自你 X 月 X 日的訪談」。

三種都一樣：透明度區塊寫明今天實際讀到的只有什麼、然後給**一個**他做得完的下一步（接上哪一個來源、明天會多出哪一段）。

**它有下限。** 連續三天都只能重述他自己說過的話、就直接跟他講：這樣不值得每天收、改成每週一份、或先接上某個來源。這句話比每天寄一份湊出來的簡報更留得住人。

## 找「今天最重要的一件事」

這是整份簡報最需要判斷的地方。優先序：

1. **外部對象的回覆或要求**，尤其是解除了內部阻塞的那種。客戶回信說「請提供更新報價」＋內部有四張票標著「等簽約」＝ 這就是頭條。
2. **今天到期或今天要決定的事**。
3. **跨來源的矛盾**：兩份文件對同一件事的說法不一致、某個決議跟另一個決議衝突。
4. **異常**：本來每天都動的東西今天沒動、某個數字跳出常態範圍。

若都沒有，就寫「今天沒有需要立刻處理的事」，然後直接進行程。**這句話本身就有價值**——它讓使用者可以放心。

判斷連動關係時，靠的是確定的 key：公司名、統編、專案代碼、任務 ID、人名。**不要靠語意相似度硬牽線**，牽錯一次的代價遠高於少牽一條。

## 存檔與續篇（第一次使用時要建）

**每次排程都是全新的 session，沒有記憶。** 所以簡報要存進 Notion，而且每天產出前要先讀昨天那一列——這樣才能寫出「昨天建議你做的那件事，他已經自己做完了，可以放掉」這種續篇。

**幫使用者關掉一件事，跟給他一件新的事，價值是一樣的。**

**存檔要標明是 AI 產出**（欄位見 `references/setup.md`）。存檔只有一個用途：讓明天的簡報接得上今天——**它不是其他 agent 的事實來源**、要引用裡面的數字就回原始系統重查。少了這條、AI 摘要會被當成事實層層轉引、錯一次就越滾越大。

第一次使用時要先建立存檔資料庫。建立方式、欄位、以及為什麼一定要建在使用者的**私人**空間（Notion 沒有逐列權限，共用資料庫等於把每個人的簡報攤開給所有人），見 `references/setup.md`。

## 個人設定檔

每個人的簡報長得不一樣。設定檔記錄他要哪些模組、關心哪些專案與對象、以及不想看到什麼。

**設定檔是長出來的，不是問出來的。** 第一天先只給骨架——人在還沒看過之前，不知道自己想要什麼。等他看過三天，他的回饋會非常具體（「不要再給我差勤簽核」「我想看廣告名單的轉換」）。那時候再更新設定檔。

### 從訪談接手（`interview-me`、原名 `my-context`）

那場訪談留下兩份東西：一份現成的簡報設定（角色、模組、關注對象、不要出現什麼、資料來源）、一份逐題寫下來的記錄檔。**先找、不要重問。** 順序：

1. 這場對話裡剛跑完訪談 → 直接用它交出的「每日簡報設定」、欄位對得上 `references/profile.md`
2. 沒有的話、用他的名字去找訪談記錄檔（檔名長得像 `2026-08-28-jason-廣告要不要繼續投.md`、放在團隊知識庫或訪談成品那個資料夾）。讀「現在的結論」與「待補清單」兩段就夠
3. 兩份都找不到、才走下一節的第一次設定選單

接手時的四條：

- **不要重跑 onboarding 問一輪。** 他剛被問了四十分鐘、再問一次會顯得這兩個東西沒有連起來
- **待補清單上的東西不要自己填答案。** 每一條後面都標著誰能答——需要它才寫得出來的那一段、就寫「這裡缺什麼、要問誰」、名字照抄
- 訪談通常已在第①站交過**骨架版**——這裡產的是模組完整版：沿用骨架版的資料與版式、加上設定裡挑的模組、**不重跑第一站已做過的查詢**
- 設定裡若列了三個以上模組、**第一份先挑最相關的兩個**——「第一天只給骨架」的原則不變、多的留給他看過再加

這第一份的定位是**樣張**：讓他看到自己的簡報長什麼樣、決定要不要每天收。所以視覺要做完整、內容寧可少而準。產完問他一句要不要排程、**不要自作主張排**——排程要他自己點頭、還要走權限預授那一步。

### 第一次設定：出一題選單、不要開放式問答

沒有訪談設定可以接的時候、第一次**只問一題、而且是選擇題**。先自己看他連得到什麼（信箱、行事曆、任務系統、筆記、公司的資料入口）、從那裡推出 3–5 個方向讓他對號入座：

```
你早上最想先知道哪一種事？（可複選）
1. 有人在等我回覆——信裡點到我、但我還沒回的
2. 今天的會、哪一場要先準備
3. 我負責的案子有沒有卡住
4. ⟨依他實際連上的來源再補一項⟩
5. 都不是——我用說的

回編號就好。
```

選項要從他**實際接了什麼**推出來——他連不到廣告後台就不要給「廣告成效」、那是在展示簡報做不到的事。這一題決定的只有頭條往哪裡找、以及最多再加一個模組、**答案先不要寫進設定檔**、設定檔等他看過三天再填。他答完直接產第一份、不要問第二題——再多問就變成問卷、問卷會讓他覺得這是一件要先投入才有回報的事。

設定檔的存放與演進方式見 `references/profile.md`。

## 語氣：說人話

簡報是每天要被讀的東西，被嫌「文謅謅」一次就會開始被跳過。每一句過三個測試（茶水間／新人／第一句），術語走換詞表——規則見 `references/plain-talk.md`。**數字、來源、人名不簡化**；其他一律講到昨天報到的新人也聽得懂。

## 視覺

輸出為 HTML 時，照 `references/visual-spec.md` 的規範走。全公司的簡報要看起來是同一份東西——這對「這是公司的制度而不是某人的實驗」這件事很重要。

若已設定品牌 design system，讀取它的 tokens 覆蓋預設值；沒有設定就用預設的 MONO 規範。

## 成本

每天跑、多來源查詢，成本會累積——而且組織有月費上限（已經真實撞過一次）。三條規則：

- **模組跟著設定檔走，不要每天全模組都跑。** 骨架加三個以內的模組是常態；設定檔要求更多時，先問使用者要換掉哪一個。
- 昨天的存檔就是為了不用重建昨天的認知——**讀過的來源不重複掃**，續篇從差異開始，不從全量開始。
- 試點期（前三位使用者）每份簡報在透明度區塊順手記一句「今天大約查了幾次資料」，回報給計畫負責人估算全員成本。

## 排程

驗收通過之後才排程。驗收的判準建議設成：連續三天，使用者每天能指出 **0 個**「這不該出現」，且**至少 1 個**「我原本不知道但該知道」。

第二條才是真正的門檻。只符合第一條的簡報是安全的，但沒有用。

**排程上線前，先手動跑一次完整流程，並在每個權限詢問出現時選「Allow for all scheduled runs」。** 排程是無人值守的——權限沒有預授，簡報會每天卡在等審核（這件事已經真實發生過一次：排程在早上 8:10 觸發，卡在 Notion 搜尋的權限確認，整份簡報停在半路）。
